# MacDNS agent instructions

How the system is built and why: `docs/ARCHITECTURE.md`. Read it before designing a change.

## Working rules

- Read the existing code before changing anything. Change only what was asked, with no extra refactors.
- No comments about removed code, no narration.
- Logs: error and warning say what failed and why, info records the healthy lifecycle, debug records the decisions needed to troubleshoot once enabled. Log each event once, where its cause is known, and never log expected churn or routine success.
- **Never commit without explicit user approval.**
- While iterating, validate only what changed: `make format`, the targeted tests (`swift test --filter <TestClass>`, `cd rust-resolver && cargo test -p macdns-resolver --lib -- <test_name>`) and `swift build --target <Target>` for Swift changes without tests. Run `make lint-invariants` when a change touches a critical invariant below.
- `make ci` is the full gate. Run it only before a version bump, a tag or a push. `make help` lists every target.
- `appcast.xml` at the repository root is the live Sparkle feed. Every shipped build reads it from `main` (`SPARKLE_FEED_URL` in `helper.mk`), so never move, rename or delete it. The DMGs it points to are the GitHub releases of this repository.
- Releases come from `.github/workflows/release.yml` on a `vX.Y.Z` tag that matches `VERSION` in `helper.mk`, pushed after its commit reaches `main`. It skips `make ci` and publishes only after the CI workflow passes on the same commit. It publishes the GitHub release and opens a separate pull request for `appcast.xml`, which is merged last, after the DMG is checked. Do not make the workflow push `appcast.xml` to `main`.
- `make release` is the release command in CI and locally. It runs `Scripts/release.sh`, which sets up signing from the same variables (repository secrets in CI, `.env` locally, listed in `.env.example`) and runs `make release-build`.
- The Keygen trial token reaches the build only through `KEYGEN_TRIAL_TOKEN`, which fills `KeygenTrialToken` in the Agent's Info.plist. Never commit a token. A release build fails without it.

## Rejected paths

Each of these was built or proposed and turned down. Do not bring one back unless asked.

**App**
- Window positioning code. Settings and first-run windows open where macOS places them.
- `Picker(...).pickerStyle(.segmented)` bound to a `@Published` value. It writes its binding during the view update and logs a fault on every click. Use `SegmentedPicker` (`SegmentedPickerTests`).
- A user denylist for Block on the Queries page. Block writes two Local Records (A `0.0.0.0`, AAAA `::`) through `LocalRecordShortcut`, so history reports the lookup as a Local Record.
- Doing anything before the user consents in first run. The window installs nothing, creates no trial and triggers no macOS prompt until the user clicks Turn On or Continue, closes it or quits. The App never creates the trial.
- Setup steps that advance by themselves, a window kept above others, or saved setup progress. There is one step per macOS request the App triggers and can read back, each with its own Continue. Local network access is only a note, because no reliable way to read its answer exists.
- Raising the XPC timeout to cover a late Agent at boot. Until the App has loaded the Agent's state, `isEnabled` is unknown, not false: a timeout retries with backoff, lifecycle actions require `.loaded`, and a timeout never triggers the `state.json` fallback.
- Probing, killing or waiting on the Agent's PID when replacing it. See Upgrades in `docs/ARCHITECTURE.md`.

**Agent**
- Holding `lifecycleLock` or a serial queue across `startServices()` or `stopAllServices()`. The lock guards only the flag check-and-set, because `startServices()` calls `stopAllServices()` on its error paths and would deadlock.
- A second writer of blocklist settings. They live under the `blocklist` key of `state.json`, which XPC strips in both directions. Only the Agent writes `blocklist_settings.json`, a copy derived for the Rust scheduler.
- Any proxy-control trust material besides the mutually code-signed XPC connection and the memory-only HMAC session: App Group files, shared `UserDefaults`, UNIX sockets, Keychain, public-key schemes, persisted secrets, a relay through the App, provider-to-Agent push, heartbeats or staleness timers.
- Importing `Shared` from an extension. Shared extension code goes in `SharedExtensionKit`.
- A reserved lane for proxy-control challenges (a UDP challenge without a permit, a reserved TCP slot). Challenges pass the same admission limits as every query (`UDP_MAX_IN_FLIGHT`, `TCP_MAX_CONNECTIONS` in `listener.rs`). Instead, the resolver admits more UDP queries than the DNS Proxy can have pending (`ResolverSocketPool.maxPendingQueries`), the Agent raises its descriptor limit (`AgentFileDescriptorLimit`), and the provider repeats one unanswered 3 s probe round before it bypasses (`DNSProxyProbeRetryPolicy`). An answer that fails validation, an authenticated `ready = 0` or a lost session still bypass at once (`ResolverAdmissionCapacityTests`).
- Widening the Keygen trial token. It only creates trials. A feature that needs more Keygen permissions needs a server endpoint.

**Resolver**
- Local DNSSEC validation on the provider path, forwarding the client's DO bit, and validation on forward, stub, DHCP or captive paths. See Resolution model in `docs/ARCHITECTURE.md`.
- Building provider slots on hickory's `Resolver` or on a raw `NameServerPool`.
- An IPv4 or IPv6 preference setting.
- Reacting to a provider closing a connection, waiting for an idle provider before rotating, or learning each provider's connection limit. Provider connections rotate by age alone: each provider's maintenance loop (`rotate_aged_conns` in `providers.rs`) replaces a `Ready` slot once its generation is 500 s old (about 512 s with the 30 s tick), one slot at a time, and publishes the replacement only if it answered its probe (`replace_conn`). Quad9 closes DoH connections about 600 s after opening them, without a GOAWAY. rustls stops reading after `close_notify`, so a close observer can miss it. A query in flight finishes on the connection it was leased on. The rotation tests in `providers.rs` guard this.
- Logging provider connection successes. Only failures are logged: the h2 shutdown summary (`provider_transport_trace.rs`) only when the peer closed, sent a GOAWAY or reset, or an I/O or stream error occurred, and `replace_conn` only when a replacement could not be built or did not answer, as a warning.
- The SRV record type, and `_` in owner labels. Swift and Rust validators reject both, and the generic zonefile parser must not bring SRV back.
- Warming popular hosts only on start, wake, network change or while the Mac is in use. Popular-host prefetch runs all the time with the normal prefetch window.
- A timer that reopens the history database or a longer wait in `History::configure`. A database that cannot open is retried by a later lookup, at most once a minute (`OPEN_RETRY_INTERVAL`).

**License**
- Any grace that a signed Keygen answer does not back, including running before Keygen holds a trial or license for this Mac. A fresh install that cannot reach Keygen stays off and the license retry creates the trial later.
- Offline grace without comparing the machine fingerprint to the signed receipt.

## Critical invariants (violating these causes production incidents)

`make lint-invariants` quotes these bullets. Each rule anchors on a phrase in its bullet, so keep the phrases when editing.

- `state.json` is the single source of truth for user config. Never split state. The App's file fallback uses the same file and stays a fallback for when the Agent is unavailable, never a parallel persistence model.
- The agent is a user LaunchAgent, not a root LaunchDaemon. Do not add root-only assumptions, `/Library/LaunchDaemons`, port 53 binding, or privileged-helper flows.
- DNS Proxy: always return `true` from `handleNewFlow`. Uses BSD sockets and `pthread_rwlock` — never change lock type or put `Network.framework`/`SCDynamicStore` work on the query hot path.
- DNS Proxy `SCDynamicStore` callbacks must only enqueue async reload work. Never call `SCDynamicStore*` synchronously from the callback, or configd can deadlock or reenter.
- Content Filter must allow MacDNS's own binaries (`MacDNSAgent`, `app.macdns.dnsproxy`, `app.macdns.contentfilter`) by source path before dropping DoH/DoT. Use `proc_pidpath` from the audit token. Security framework process lookup fails from the sandbox.
- XPC security uses audit token via `CodeSignValidator`. Never bypass it, never use `kSecCSStrictValidate`.
- Proxy-control plane is fail-closed: the provider leaves bypass only after mutually code-sign-validated XPC (requirements in `ProxyControlProtocol.swift`), an installed HMAC session, authenticated UDP **and** TCP TXT challenges answering `ready = 1`, and non-empty DNS destinations. XPC interruption or invalidation destroys the session and forces bypass immediately. Never re-add a libproc/`proc_*` endpoint validator — the NE sandbox denies it.
- The HMAC session key is ephemeral and memory-only (provider, agent, Rust resolver). Never persist, log or send it to the App, or put it in `state.json`. Install and clear it via `dns_configure_proxy_control` / `dns_clear_proxy_control`. `dns_init` resets the session before listeners open.
- Darwin notifications are unauthenticated wake-up hints only. They may enqueue health evaluation but never directly change bypass, readiness, or displayed state.
- Provider interception state (`bypass(reason)` / `intercepting`) reaches the App only inside the agent's `getRuntimeState` snapshot. When the provider can't be queried the agent reports `unknown` — never guess `intercepting` from `NEDNSProxyManager.isEnabled`. The report carries `providerVersion` so the App can detect a stale extension after an update and prompt a restart.
- `state.json` writes are revision-guarded (`configRevision` via `ConfigRevisionPolicy`: accept, idempotent success or conflict) and serialized through `StateFileLock` (flock on `state.json.lock`), for the Agent and the App fallback alike. A conflict never silently overwrites. The App resends a save that lost its revision once, and only when every value it writes still holds the value the edit started from. Otherwise it drops the edit, shows the authoritative configuration and tells the user.
- A fresh install must always reach Enable. `enableDNS()` and the first-run trial step are the only callers of `installAgent()`. Every `AgentInstaller.install()` runs through `AgentInstallSerializer`, so no two installs overlap, and the Agent replacement unregisters inside the same serialized run. The agent bootstraps `state.json` (`isEnabled: false`) on every launch and creates the Keygen trial, so no App gate may require agent-owned state before the first Enable. Agent not runnable and no `state.json` is `PersistedStateAvailability.agentSetupRequired`, which allows only Enable. The App never refuses Enable for an `.unknown` license (`FreshInstallOnboardingTests`).
- License is fail-closed via the durable `LicenseFailClosedLatch`. Only an authoritative license transition that persisted successfully clears it. Network grace, timers and in-memory parses never do. Engaging the latch always arms the license retry (`engageFailClosed`), and so does a periodic check skipped because another license operation held the gate.
- Offline grace rests only on the signed receipt (`validationReceipt`: the last `validate-key` answer with its `Date` and `Keygen-Signature`). `handleNetworkErrorFallback` verifies it with the pinned account key and takes the validation, expiry and machine from the signed body (`LicenseManager.offlineProof`). Grace is 72 h from the signed date, only for this license and only when the hardware fingerprint matches. Never use `status`, `expiresAt` or `lastValidatedAt` from `license.json` for grace, since the file is user-writable. Online, Keygen's answer decides. Every verified answer replaces the receipt (`LicenseOfflineProofTests`, `LicenseMachineReactivationTests`).
- Every Keygen request ends within `LicenseRequestBudget.perRequest` (10 s, in `Shared`), and no license operation sends more than `maxRequestsPerOperation` requests in a row. The App's license deadlines (`XPCClient.licenseReplyTimeout`) and the Agent's wait for a concurrent validation derive from `LicenseRequestBudget.operation`. A change that adds a request to a license chain raises `maxRequestsPerOperation` in the same change (`testNoLicenseOperationExceedsTheBudget`).
- The periodic license validation runs only while services run (`LicenseManager.setServicesRunning`), called only while holding `lifecycleLock`, so a stop racing a start always leaves validation stopped.
- The machine fingerprint is derived from hardware by `MachineFingerprintPolicy` on every use and never stored, cached or read back as an identity. The receipt's fingerprint is only compared with it. The formula is the 1.x one, byte for byte: `sha256` of `IOPlatformUUID`, `IOPlatformSerialNumber` and `hw.model` joined by `|`, with an absent serial skipped. A failed read yields no identity and retries. An absent serial counts only when three snapshot reads agree. A new formula must try the old one before creating a trial or activating a machine.
- Service start: `ResolverModule.start()` → `proxyEnable` → `bypassDisable`. Stop: `bypassEnable` → `proxyDisable` → `ResolverModule.stop()`.
- Concurrency flags (`isStartingServices`, etc.) MUST use `defer { flag = false }` — without it, errors leave services stuck.
- Agent-originated external network work (initial update check, blocklist scheduler/force refresh) is gated by `NetworkReadySignal` until the first captive-portal `.normal` or the 30 s fallback, because Content Filter activation can kill in-flight connections. Do not start those URLSession/reqwest paths earlier, do not replace the gate with retries on `-1009`/ENETDOWN, and do not release it on inferred state.
- Allowlist and blocklist use LMDB with hot reload (`dns_reload_blocklist`). Never restart the module for list changes. Allowlist I/O goes through `dns_allowlist_*`. Blocklist updates run as a scheduler inside `macdns-resolver`, reading `blocklist_settings.json` via `dns_configure_blocklist`.
- DNS override and forward-zone state is held in memory in the Rust resolver. `state.json` remains authoritative: `applyOverridesAndZonesToModule()` replays it on every `startServices()` and `saveFullConfig()`. The resolver applies it as one validated snapshot published atomically via `ArcSwap` (`policy.rs`). Never clear and reinsert on live stores. A rejected entry leaves the previous policy intact.
- `libmacdns_resolver.dylib` is loaded once per agent lifetime via `dlopen` and must be signed `codesign --options runtime` matching the agent identity, or `dlopen` fails under hardened runtime. `ResolverModule.stop()` tears down tasks and the Tokio runtime but never `dlclose`s. A later `start()` reuses the same handle.
- FFI contract: every Rust `extern "C"` entrypoint must catch panics and return a sentinel (`0` / `-1` / `NULL`). Swift callbacks handed to Rust must be non-capturing C callbacks. Rust-owned C strings are freed only by the matching `dns_*_free_*` function.
- Lookup history is data, not configuration. Only its four settings (`queryHistoryEnabled`, `queryHistoryRetentionDays`, `popularPrefetchCount`, `popularPrefetchDays`) live in `state.json`. The App never opens `query-history.sqlite` and reads it only through the Agent (`queryHistory`, `clearQueryHistory`). The query hot path builds a `LookupEvent` and does a non-blocking send, and a full queue drops and counts. `handle_wire` records exactly one event per client lookup. Prefetch refills, probes and proxy-control challenges never count. A broken history answers `unavailable` and never stops resolving or fails `start()`. Turning history off stops recording and keeps the database. Only Clear History deletes it, and it reports success only when the files were deleted. The save transaction applies history last, because its rollback does not reapply history settings.
- Resolver policy that is Rust-internal stays out of `state.json`: DNS rebinding defense, built-in special-use local zones, cache TTL bounds and RRset round-robin are not user settings. Pre-public route precedence is fixed (`select_pre_public_route` in `query.rs`), all before cache and public DoH: user forward/stub zones → captive-protected built-ins (`.onion`, RFC1918 PTR) → ephemeral DHCP routes → RFC 6761 `localhost` → RFC 8880 `ipv4only.arpa` → blanket `CaptiveForward` → remaining built-ins (`.local`, DHCP search domain) → cached-ancestor NXDOMAIN. Only the remaining built-ins sit below `CaptiveForward`, because portal sign-in depends on the hotspot resolver answering them.
- DNS64 (`dns64.rs`, `network_profile.rs`) is a per-network view, not cached data. Synthesized AAAA records are built at response time and never enter the answer cache or the dump. Every `dns_apply_network_snapshot` starts a new generation that drops the NAT64 prefix at once. Synthesis resumes only after RFC 7050 discovery against the primary service's own resolvers (never `Global/DNS`, which a VPN replaces) confirms prefixes, and stops when that answer's TTL ends. Unknown or lapsed discovery means no synthesis.
